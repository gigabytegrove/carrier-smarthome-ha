# One-time Matter onboarding design (v0.5.7b2, unpublished)

Carrier SmartHome is a Home Assistant custom integration installed through HACS.
It cannot safely install a privileged background Matter daemon or manage the
container host. We therefore reuse **the official Home Assistant Matter fabric**
where available, rather than creating a second controller. The Carrier integration
remains the user-facing climate entity and offers native cloud/local control
preferences, with one Carrier account and device identity.

## What the software actually automates

- From Carrier SmartHome → Configure, select an existing Carrier thermostat and
  choose Cloud only, Local Matter only, or Prefer Matter.
- If the official Matter integration has a **loaded** config entry, resolve its
  server address from that entry rather than asking for a WebSocket URL.
- Query only the already-commissioned, available nodes; filter by the documented
  Carrier Matter VendorID and ProductID and the Thermostat cluster at a valid endpoint.
- Choose from matching nodes and explicitly confirm that the selected Matter
  device and Carrier cloud serial represent the same *physical* thermostat.
- During confirmation perform actual read-only Matter telemetry and pin the
  selected native Matter config entry plus its compressed fabric ID.
- Preserve an existing Matter-only choice when the native controller disappears.
  Never silently move an existing Matter-only entity back to cloud.
- Preserve the advanced manual private-IP path for migrations and power users.

This **does not** commission the device or install a Matter controller by itself.
It does **not** silently disable/hide climate entities generated by the official
Matter integration, alter Home Assistant's Matter device registry, or copy the
official controller's fabric keys into Carrier SmartHome.

## Home Assistant OS

The official Matter integration installs and manages the supported Matter Server
app. The thermostat is paired/shared with that integration using Home Assistant's
supported flow (often the Companion app). After that Carrier detects it and
no longer asks for Matter Server host/port or node IDs. No Carrier-specific
controller is installed. The built-in controller is the single source of fabric
credentials. This uses the supported OS pathway.

## Home Assistant Container / standalone Docker

Home Assistant Container has **no Supervisor apps** and cannot install a Matter
controller via a HACS component. Matter's CASE commissioning and control require
a dedicated controller, persistent secure fabric storage, IPv6 and multicast.
Running an embedded controller inside Home Assistant would require a new
full-stack SDK integration plus platform-native binaries and lifecycle support.

Container operators need a managed Matter Server instance (once per HA instance),
then configure the official Matter integration against it. Carrier automatically
detects that configuration and presents commissioned Carrier thermostat devices.
A **single Docker Compose bundle** for new deployments could provide both
Home Assistant and Matter Server under one deployment. That bundle is not part
of the HACS payload and must not overwrite an existing user's Compose setup.

## Hardware/platform limitations

- Pairing requires legitimate commissioning credentials or a multi-admin share.
  Do not log or upload pairing codes. The manufacturer's Wi-Fi QR is not
  necessarily a Matter commissioning QR.
- IPv6 link-local on a VLAN can work with devices on the same segment; packet
  reachability and mDNS still must be tested. IPv4 DHCP alone is insufficient.
- Official Matter pairing can produce an additional Home Assistant climate
  entity; Carrier does not automatically remove another integration's entities.
  Users may hide the unwanted native Matter entity in the Home Assistant UI.
- Matter-only mode still requires Carrier account discovery at cold startup in
  this beta. Cloud-independent cold startup needs verified persistent identity
  storage and is not claimed.
- Never auto-fallback a Matter write through cloud once a write might have been
  transmitted.
- The v0.5.7b1 GitHub beta tag is immutable and remains separate from the
  v0.5.7b2 development branch.

## Test gates before a new beta tag

- Offline tests: `python3 -m unittest discover -s tests -v`.
- Confirm active native Matter config entry discovery on HAOS and on HA
  Container with an externally provisioned Matter Server.
- Confirm native Home Assistant Matter hostname URL works only when derived
  from a loaded official Matter config entry.
- Test incorrect fabric ID, lost native Matter config entry, multiple identical
  thermostats, connection loss and user selection errors.
- Confirm existing cloud-only users see no changed entities or control behavior.
- Verify one-at-a-time supervised physical HVAC mode and temperature changes.
